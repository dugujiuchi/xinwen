## 标准更新流程

### 1. 本地提交推送

```bash
cd D:\Work\ai_websearch\web_aisearch
git add <具体文件>        # 不要用 git add -A（工作区有临时脚本时会误提交）
git commit -m "说明"
git push origin main
```

### 2. 服务器拉取 + 重建（1Panel 终端，建议进 tmux）

```bash
tmux new -s deploy        # 已有会话则 tmux attach -s deploy
cd /opt/xinwen/web_aisearch
git fetch origin
git reset --hard origin/main      # 服务器无本地改动，reset 比 pull 干净、不会冲突
docker compose up -d --build      # 重建 api/crawler/nginx，postgres 与数据卷不动
```

### 3. 验证容器真的换了（重要：构建中断时不会自动生效）

```bash
docker compose ps
```

- `CREATED` 列应为 **a few seconds ago**（显示 weeks/months ago = 还是旧容器，重建没生效）
- IMAGE 列应为 `web_aisearch-*` 标签（显示 `sha256:xxx` = 上次构建中断的悬空镜像，必须重新 build）

### 4. 数据侧操作（按发布内容需要，均可幂等重复执行）

```bash
docker exec news-api python -m scripts.clean_duplicate_news     # 重复数据清理
docker exec news-api python -m scripts.clean_news_tags --apply  # 垃圾标签重置
```

新增/变更数据源配置：改 `backend/scripts/seed_sources.py` 即可——api 启动时种子 override=True 会

自动更新库中源的 crawl_type/config（保留 is_active / display_name / category / sort_order）。

### 5. 管理端收尾（浏览器 http://服务器IP/admin，密码见 .env 的 ADMIN_PASSWORD）

- 数据源启用/停用（种子机制管不了 is_active，停用类操作必须手工点）
- 触发全量爬取，看「爬取日志」确认各源条数
- `docker logs news-crawler --tail 30` 看有无异常（正常结尾：`本轮抓取完成: 成功=N 失败=0`）

## 踩坑经验（真实发生过的）

1. **1Panel 网页终端断线会杀掉前台命令**。长任务（构建、爬取测试）一律进 tmux：`tmux new -s deploy`；`Ctrl+B` 松开按 `D` 挂后台；`tmux attach -s deploy` 接回。
2. **构建中断 ≠ 部署生效**。compose 客户端被杀后旧容器继续跑；必须用标准流程第 3 步核对 `docker compose ps` 的 CREATED / IMAGE 两列。
3. **1Panel 终端粘贴可能带入 `^` 字符**：报 `Command '~xxx' not found` 时删掉行首 `^` 重敲。
4. **私有仓库需要 PAT**（GitHub 已不支持密码认证）。本项目已转 public，服务器匿名 fetch 即可。若将来再建私有库：GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → 勾 `repo` scope → 服务器 `git config --global credential.helper store` 后首次输入 用户名+token。
5. **2C2G + 3Mbps 对浏览器源很吃力**：modelscope 服务器上要 3.5 分钟且渲染不全（本地 16 秒 40+ 条），全量一轮约 10 分钟；调度器有单源 10 分钟超时保护，卡住的源不会拖垮整轮。优化线索（未实施）：魔搭研习社有 JSON 接口 `POST https://modelscope.cn/api/v1/dolphin/articles`，body 如 `{"PageSize":20,"PageNumber":1,"Type":2,"Sort":"hot","Query":"前沿技术","IsCourse":[0,1]}`，列表在 `Data.Articles`，字段 `Title/Url/Desc/GmtPublished(unix 秒)/Tags`，可改 api 型源免浏览器渲染。
6. **`git reset --hard` 不会动 `.env`**（gitignore）和 pgdata 卷，服务器配置与数据安全。
7. **误提交临时文件的补救**：`git rm --cached <file> && git commit --amend --no-edit`。
8. **Playwright 同步 API 绑定创建线程**：工作线程模式抓取时浏览器必须 thread-local + 线程退出前显式关闭（见 browser_crawler.py 注释），改抓取线程模型时别破坏这一点。
9. **去重依赖稳定 link**：带追踪参数（request_id/utm_* 等）的源由 `BaseCrawler.canonicalize_link` 入库前归一化；同批次内重复链接（页面多处展示同一文章）由 manager 的 seen_links 集合兜底。
